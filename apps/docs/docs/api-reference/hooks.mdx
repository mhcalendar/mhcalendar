# Hooks

`@mhcalendar/react` doesn't export any custom React hooks today. It's a thin, generated wrapper
around the Stencil component (three `createComponent()` wrappers plus re-exported types).

In practice this means:

- **Event state** — keep `events` in whatever state mechanism your app already uses
  (`useState`, a store, server state) and update it inside the
  [interaction callbacks](/docs/components/calendar/events#interaction-callbacks). No
  `useCalendarEvents()`-style hook is needed or provided.
- **Reading calendar state** — there's no `useCalendarApi()` hook; call the async
  `getApi()` method on a ref instead, as shown in
  [Basic usage](/docs/components/calendar/basic-usage#reading-state-back-out-with-getapi).

If a common pattern here (e.g. wrapping `getApi()` in a hook) turns out to be worth standardizing,
it would be a good candidate for a future release — check the [Changelog](/docs/changelog).
